# 参数化斗拱建模系统 · 设计说明

## 一、总体架构

```
用户参数（铺作类型/材等/跳数/昂制/材质）
        │  JSON（UTF-8）
        ▼
┌─────────────────────────────────────────────┐
│  dougong-core（纯 Rust，无平台依赖）          │
│  材分制推算 → 构件几何 → 榫卯分层装配          │
│  → Assembly（网格+TRS+材质+说明）             │
│  → 标准 GLB 导出                              │
└─────────────────────────────────────────────┘
        │ cdylib + C ABI（dg_generate/dg_generate_glb）
        ▼
dougong-wasm（wasm32-unknown-unknown，无 wasm-bindgen）
        │  线性内存传 JSON / GLB 字节
        ▼
Web 前端（WebGPU）
  阴影贴图 → 相机深度 → SSAO+模糊 → PBR 主通道
  爆炸/拆装位移全部在顶点着色器按 uniform 完成
```

- **核心与平台解耦**：`dougong-core` 不依赖任何浏览器 API，可在原生环境跑单元测试（`cargo test`），
  也可编译成 WASM。几何推算逻辑只有一份。
- **WASM 边界零框架**：不用 wasm-bindgen，纯 C ABI + 一块静态结果槽，
  产物仅约 280 KB，前端用原生 `WebAssembly.instantiate` 加载。
- **动画不重建**：顶点在 CPU 侧一次性烘焙到世界坐标，同时携带 `(构件id, 层号, 拆解方向)`；
  爆炸视图与逐层拆装只改两个 uniform，在 GPU 顶点着色器里位移，不重新上传缓冲。

## 二、材分制推算（有法式依据的部分）

### 2.1 材与栔
- 材广 15 分°、材厚 10 分°；栔广 6 分°、厚 4 分°；足材 = 一材一栔 = 21 分°。
- 八等材实际尺寸按《营造法式·卷四·材》所记宋寸，**1 宋尺取 0.312 m**
  （学界常用 0.31–0.32 m 区间的中值；换用其他尺长只需改 `caifen.rs` 一个常量）。
- 1 分°的实际长度 = 材广实物 / 15。例：五等材广 6.6 宋寸 = 0.2059 m，
  得 1 分° ≈ 13.73 mm，与程序输出 `fenM=0.01373` 一致。

### 2.2 斗
| 构件 | 长（分°） | 宽（分°） | 高（分°） | 依据 |
|---|---|---|---|---|
| 栌斗 | 32 | 32 | 20 | 《法式》栌斗长三十二分°，斗高耳平欹 2:1:2 |
| 散斗/交互斗/齐心斗 | 16 | 14 | 10 | 《法式》小斗制度 |

斗分耳、平、欹三段，比例 2:1:2；欹段向下收分，底口取斗长的 0.8。

### 2.3 栱
- 截面：华栱、昂等受力构件用足材 10×21 分°；横栱用单材 10×15 分°。
- 栱长：令栱 72、瓜栱（瓜子栱）62、万栱（慢栱）92 分°。
- 出跳：每跳 30 分°（《法式》「每跳之长，不过三十分°」）。
- 栱端卷杀：四瓣，每瓣收 1 分°、降高累加，端部总降高约材高的 1/3。

### 2.4 铺作命名与跳数
外跳跳数 = n 时称 (n+3) 铺作：四铺作一跳、五铺作两跳……八铺作五跳。
本模型内外对称，里跳跳数同外跳；可关闭里跳只生成外跳半朵。

## 三、法式未规定死数、由本模型判断的部分

《营造法式》对下列细节只述做法、未给可直接套用的数值，本模型取参数化判断值，
均集中在 `caifen.rs::Rules`，便于研究者调整对照：

1. **昂身斜率**：取降 2 分° / 平 5 分°（倾角约 21.8°）。
   法式只讲「斜下」「昂身过斗心」，宋构实例斜率多在 20°–25°，取中值。
2. **昂尾（挑斡）水平长度**：40 分°，使昂尾能压过内跳一华栱。
3. **昂嘴形制**：距外端 12 分°处底面开始上抬，端部留上部约 9.5 分°高，做成尖喙。
4. **耍头蚂蚱头**：削斜段长 12 分°，端部由足材 21 分°削到 8 分°高。
5. **卷杀分段长度**：卷杀段取栱长的 1/4，四瓣均分。
6. **榫卯表达**：不做布尔开槽（实时重建与轻量化要求），
   改为栱/昂底嵌入斗耳上口 2 分°，视觉与层级上表达「榫头入斗口」的咬合关系。
7. **横栱轮换**：最外跳施令栱；内跳奇跳施瓜栱、偶跳施万栱，
   对应「瓜子栱上施慢栱」的逐层简化。

## 四、几何与装配约定

- 坐标系：X 面阔、Y 进深（外跳为 +Y）、Z 竖直向上；原点在栌斗底面中心。
- 构件局部网格以「分°」为单位建模，输出装配时统一乘以 `fen_m` 换算到米，
  平移量同步换算，旋转角无量纲不变。
- 网格图元：盒体（斗的耳/平段）、带卷杀轮廓的多边形拉伸（栱）、
  任意多面体（斗欹台体、昂、耍头），耳切法处理凹多边形端面，平面法线。
- 拆装层号：栌斗=0，每跳一层，耍头在最上层；同层构件共享拆解时间窗。

## 五、渲染

- **材质**：木纹与宋式彩画（丹粉刷饰）均为 Canvas 程序化生成，无外部图片资源。
  木纹含纤维、年轮、节疤；彩画含朱红叠晕边带、六瓣团花、锦地点缀。
- **光照**：半球环境光（天空/地面按法线 z 混合）+ 平行主光（带 3×3 PCF 阴影）
  + 相机方向补光，双面光照（翻转背向相机的法线），保证绕序不齐的图元也正确受光。
- **SSAO**：相机深度 → 视图空间重建位置与法线 → 16 核半球采样 → 5×5 模糊，
  主要强化斗栱咬合缝隙的接触暗化。
- **颜色管线**：纹理用 srgb 格式（采样自动转线性），线性空间着色后手动 Reinhard
  tonemap + sRGB 编码输出。材质基色只做 35% 轻度色调调制，避免与纹理色全强度相乘
  把木作暗部压成死黑。

## 六、性能与验证

- 最大朵八铺作（42 构件、约 1600 三角面）WASM 推算约 0.1 ms 量级，
  含 GPU 缓冲重建的前端总重建实测 11–43 ms，远低于 1 秒要求；UI 另加 250 ms 防抖。
- Rust 侧 6 个单元测试覆盖：材分尺度、六种铺作生成、昂制/半朵、
  GLB 容器合法性、JSON 往返、重建耗时预算。
- GLB 通过 Khronos 官方 `gltf-validator` 校验（0 error / 0 warning），
  按材质拆 primitive、根节点做 Z-up→Y-up 旋转，可直接导入 Blender 等软件。

## 七、已知取舍

- 三角形绕序在不同图元生成路径间不统一，前端关闭背面剔除、靠双面光照保证正确；
  对千级面模型无性能压力，后续可在 Rust 侧统一绕序后开启剔除。
- 榫卯为嵌入表达而非真实开槽布尔运算，属教学展示模型的有意简化。
- 未做斗子斫卯口、栱眼等细小特征的独立网格，以卷杀轮廓和分段材质传达形制。
